# Version 1.0.0 — stable release candidate

**Unreleased.** This note describes the implemented candidate and accepted
staging behavior. Publication requires the remaining
[release gates](../v1.0.0-release-checklist.md); it does not promote production.

## Calendar delivery

The stable target combines nine qualified automated authorities with reviewed
manual schedules. See the [supported-scope
table](../../README.md#supported-scope)
for exact season/stage boundaries. The service preserves stable identities,
processes schedule corrections and explicit lifecycle changes, and retains
last-known-good state when a source fails. Independent provider and Outlook
jobs prevent a failed source from stopping other scopes.

Manual imports use persistent profiles, schema validation, previews, exact
approvals and audit receipts. Separate Outlook review appointments remind the
operator to check schedules. Text/PDF extraction remains outside the runtime;
manual competitions do not become automatically maintained by importing once.

## Accepted retirement behavior

Retirement stops routine provider/manual imports, fixture synchronization and
matching review synchronization within the reviewed boundary. It reserves the
original authority and rejects pending import approvals without deleting
historical fixtures, reviews, provenance or applied receipts. Pending review
writes freeze until explicit reactivation. Future seasons need new qualified
configuration; broad grants are never implicitly split or narrowed.

The operator verified candidate `59dd553` in existing staging using two
synthetic scopes. After deactivation and restart, all four fixture/review
appointments retained IDs, content and change keys. The active control accepted
a venue correction while retired history stayed unchanged. Explicit
reactivation then allowed a reviewed correction at the original Outlook ID;
both reviews and the updated control stayed unchanged. Private evidence remains
on the staging volume. Repeated-deactivation/replay edge cases also retain
deterministic coverage. No real ongoing season was declared complete.

## Deployment and limitations

Read the [installation and upgrade guide](../installation.md) before deployment.
Use the reviewed source commit/tag: Compose builds locally and `IMAGE_TAG`
only names that build. No published GHCR image is supplied by this workflow.

Back up the entire persistent state while the owner is stopped: SQLite and
sidecars, media, manual inbox/profiles and receipts belong together. Forward
migrations are idempotent. Older images ignore the retirement gate; downgrade
requires a matching complete snapshot and Outlook reconciliation, not an image
swap on the upgraded database. Staging mappings must never be copied into a
new production calendar. Live credentials and source packages are not included.

There is no automatic provider failover, document extraction, source scraping,
fixture identity guessing or unqualified future-season expansion. Reminders and
approved media remain independently configurable. Third-party logos are not
required and are not licensed by the repository's MIT license.
