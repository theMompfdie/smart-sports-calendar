## Integration and publication

1. Operator signs the focused documentation commit; assistant verifies its
   signature and contents, pushes, prepares the PR to `develop` and checks CI.
2. Operator merges after review. Verify the resulting `develop` commit and CI.
3. Prepare a focused release change: set `pyproject.toml` version to `1.0.0`,
   finalize candidate evidence and the intended release note. Do not describe
   the tag as already published. Operator signs and merges through `develop`.
4. Prepare the release PR `develop` to `main`. Check its complete diff, CI,
   conflicts, review comments and all gates above. Operator performs the merge.
5. Verify `main` and its CI. Operator creates and verifies the signed annotated
   `v1.0.0` tag at that exact commit, then publishes the reviewed stable
   release.
6. Verify tag signature/target, release body, stable (not prerelease) status and
   absence of private attachments. Update publication records and close #201.
7. Promote production only as a separate reviewed operation with a verified
   complete backup, immutable build and target-specific acceptance. Branch
   cleanup remains a separate operator-controlled step.
