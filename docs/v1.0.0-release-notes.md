# Version 1.0.0 release notes — draft

Unreleased. This draft records implemented changes awaiting the remaining
Version 1.0 verification and publication gates. It is not a release approval.

## Completed competition seasons

Issue [#267][retirement] adds operator-reviewed preview, deactivation and
reactivation of an entire existing competition/season or disjoint stage grant.
Migration 015 persists retirement independently of source configuration, so
normal startup cannot silently resume retired work.

Retirement preserves sports events in SQLite and Outlook, source attribution,
stable mappings, provenance, import receipts and participant reminder rules.
It stops routine provider/manual imports and fixture synchronization in that
boundary, rejects pending import approvals, and explicitly completes only
matching manual review plans. Dedicated review appointments retire through
the existing retryable Graph lifecycle. Late corrections require explicit
reactivation; future seasons require their own qualified configuration.

## Operations and limitations

- Use the [season-retirement cookbook](season-retirement-cookbook.md), including
  reviewed completion evidence and an explicit correction/grace period.
- All lifecycle commands require the owning process to be stopped and acquire
  its existing OS instance lock. Pending fixture Graph work blocks retirement.
- Authority boundaries remain reserved. The CLI does not split broad grants,
  infer completion from a date, clean historical data, or provide auto-failover.
- Migration 015 is additive. Back up complete persistent state before upgrade.
  Older images ignore the retirement gate; rollback requires a matching
  pre-upgrade backup and qualification, not simply an image downgrade.
- Synthetic mocked-Graph regression coverage is provided. Isolated live
  staging of retirement, restart, unchanged rerun, retained Outlook history and
  reactivation remains outstanding and must pass before release.
